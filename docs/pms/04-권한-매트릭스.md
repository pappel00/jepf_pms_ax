# PMS 권한 매트릭스

> 확정 2026-10-28. 권한은 별도 테이블 없이 **프레임워크의 Role · 사용자그룹 · 페이지 Role 매핑**(시스템 관리 > User Management / Portal Management)에 저장한다.
> 편집은 기존 관리 화면에서 한다 — 사용자그룹의 Role(`usr_user_group_role`), 페이지의 Role(`prt_page_role`).

## 1. 결정 사항

| 항목 | 결정 |
|---|---|
| 영업·기획 | 하나(`PMS_SALES`). 필요하면 Role·그룹만 추가로 분리 |
| 수행 인력의 이슈·산출물 등록 | **불가** — 조회만. 이슈·산출물 등록/관리는 PM(프로젝트 관리자) |
| PM의 자기 프로젝트 예상 원가 열람 | **가능** (`PMS_COST_VIEW`) |
| 고객사 담당자 | PMS 미노출(Role 없음) |

## 2. 3계층 구조

| 계층 | 저장 위치 | 판정 |
|---|---|---|
| ① 메뉴 접근 Role | `prt_page_role` (페이지 ↔ Role) | 메뉴 목록 API가 사용자 Role로 걸러서 내려줌 |
| ② 행위 Role | `usr_user_group_role` (그룹 ↔ Role) | 서버 `@PreAuthorize` (승인·확정·원가) |
| ③ 프로젝트·본인 범위 | `pms_project_member`, 담당자 ID | 서버 서비스 로직 (◐ 참여 프로젝트, ○ 본인 건) |

## 3. Role 정의

**메뉴 접근 Role**

| Role | 이름 | 대상 |
|---|---|---|
| `ROLE_PMS_SALES` | 영업/기획 | 고객·RFP·제안서 담당 |
| `ROLE_PMS_PM` | 수행 PM | 프로젝트 관리자(자격). 실제 관리 범위는 프로젝트 멤버로 판정 |
| `ROLE_PMS_MEMBER` | 수행 인력(자사) | 개발·QA 등 투입 인력 |
| `ROLE_PMS_PARTNER` | 협력사 인력 | 자기 업무·진척만 |
| `ROLE_PMS_OPS` | 운영 담당 | 운영 단계 프로젝트 |
| `ROLE_PMS_MANAGER` | 센터장/경영 | 전체 현황, 승인 |
| `ROLE_ADMIN` / `ROLE_SYSTEM_ADMIN` | 관리자 | 모든 메뉴(모든 매핑에 포함) |

**행위 Role**

| Role | 권한 | 부여 그룹 |
|---|---|---|
| `ROLE_PMS_APPROVE` | 단계전환 승인·반려·롤백, 투입 변경 승인·반려, RFP 확정 M/D·재평가 요청 | `PMS_MANAGER` |
| `ROLE_PMS_COST_VIEW` | 예상 원가·인건비·단가·이익률 열람 | `PMS_MANAGER`, `PMS_PM` |

`ROLE_ADMIN` / `ROLE_SYSTEM_ADMIN` 은 위 행위를 모두 할 수 있다(서버 검사에 포함).

## 4. 사용자그룹 → Role

| 그룹 | 포함 Role | 대상 |
|---|---|---|
| `PMS_SALES` | USER, PMS_SALES | 영업/기획 |
| `PMS_PM` | USER, PMS_PM, PMS_COST_VIEW | 수행 PM |
| `PMS_MEMBER` | USER, PMS_MEMBER | 수행 인력 |
| `PMS_PARTNER` | USER, PMS_PARTNER | 협력사 인력 |
| `PMS_OPS` | USER, PMS_OPS | 운영 담당 |
| `PMS_MANAGER` | USER, PMS_MANAGER, PMS_APPROVE, PMS_COST_VIEW | 센터장/경영 |

한 사람이 여러 그룹에 속할 수 있다(예: 영업 겸 PM). 로그인 시 그룹의 Role이 합쳐진다.
